# Invariants

Each row is a claim, the tests that try to break it, and the command that runs them. Run everything with
`make test`; run one row with the command shown (from the repo root, after `make setup`).

| # | Claim | Tests that try to break it | Command |
|---|---|---|---|
| 1 | No ACCEPTED order ever breaches a configured limit (position limit, price band). | `tests/test_gate.py::test_invariant1_random_streams` (Hypothesis, random order streams through the real gate; an independent replay re-checks every ACCEPT); `::test_invariant1_concurrent_clients` (8 concurrent clients, 480 orders); `tests/test_rules.py::test_check` (every boundary: exactly at / one past each limit) | `.venv/bin/python -m pytest tests/test_gate.py tests/test_rules.py -q -k "invariant1 or check"` |
| 2 | Replaying the same log gives a byte-identical state hash, and decisions depend only on logged data, never the wall clock. | `tests/test_gate.py::test_replay_state_hash_is_byte_identical`; `::test_restart_rebuilds_state_and_dedupe` (gate restart); `::test_fsync_policies_give_identical_logs` (per_order, batched, none produce identical bytes); **`tests/test_ratelimit_replay.py`** (rate-limit window replayed from logged `ts`: gate and auditor decide identically) | `.venv/bin/python -m pytest tests/test_ratelimit_replay.py tests/test_gate.py -q -k "replay or restart or identical"` |
| 3 | Cash, positions and realized P&L reconcile after every fill; money is integer minor units, never floats. | `tests/test_ledger.py::test_identity_and_positions_after_every_fill` (Hypothesis: `cash == gross P&L - fees - open cost` after every fill); `::test_fifo_long_then_short_flip`; `tests/test_gate.py::test_invalid_orders_are_errors_not_log_lines` (float qty/price refused); `::test_fixture_matches_hand_computed_totals` (audited totals equal totals worked out by hand) | `.venv/bin/python -m pytest tests/test_ledger.py tests/test_gate.py -q -k "ledger or identity or fifo or invalid or hand_computed"` |
| 4 | A duplicate `client_order_id` returns the original decision and is never double-counted, including after a restart. | `tests/test_gate.py::test_duplicate_returns_original_and_counts_once` (same id, even with a different payload); `::test_restart_rebuilds_state_and_dedupe` | `.venv/bin/python -m pytest tests/test_gate.py -q -k "duplicate or restart"` |
| 5 | Any edit, deletion or reordering of a log line is detected and the first bad seq is reported. | `tests/test_chain.py`: edit at first/middle/last line, edit with a recomputed hash (caught on the next line), delete, reorder, whitespace-only change, partial last line, trailing garbage, and the auditor reporting the first bad seq with partial figures. `make demo` also tampers three copies of a real log. **Known gap, asserted by a test:** deleting the newest lines is not detected (`::test_known_gap_tail_truncation_is_not_detected`). | `.venv/bin/python -m pytest tests/test_chain.py -q` |
| 6 | Reconciliation never guesses: a broker row or log fill that cannot be paired one-to-one is reported as `AMBIGUOUS`, `MISSING_IN_BROKER` or `MISSING_IN_LOG`, never silently paired, and the result does not depend on CSV row order. **Exactly what evidence exists:** (a) a fixture with answers worked out by hand (12 log fills, 14 broker rows: 6 MATCHED, 2 MISSING_IN_BROKER, 5 MISSING_IN_LOG incl. two broker duplicates and one fill of an order the gate rejected, 1 QTY, 1 PRICE, 1 AMBIGUOUS; implied difference AAPL +23, MSFT -5, cash -249,100) `tests/test_recon.py::test_fixture_matches_hand_computed_answers`; (b) `::test_two_identical_fills_and_two_identical_rows_are_ambiguous_not_paired`, `::test_a_chain_of_candidates_is_one_ambiguous_component_even_if_a_greedy_pairing_exists`, `::test_an_id_on_the_row_is_never_re_matched_on_fields`; (c) a Hypothesis property over 300 random small scenarios: a pair is MATCHED only if it is the sole candidate on both sides, every other candidate is AMBIGUOUS, and every log fill and every row lands in exactly one finding (`::test_property_pairs_only_when_the_candidate_is_unique_on_both_sides`); (d) 30 shuffles of the fixture CSV and a 150-example property give identical results (`::test_shuffling_csv_rows_does_not_change_the_result`, `::test_property_row_order_never_changes_the_result`); (e) the report is byte-identical across runs (`::test_reconciliation_is_deterministic_byte_for_byte`); (f) malformed CSVs fail with the right row number, floats-as-money, epoch seconds and offset-less times are refused (`tests/test_fills_csv.py`, `tests/test_recon.py::test_malformed_broker_csv_*`); (g) a broken log chain means no reconciliation is run (`::test_broken_chain_means_no_reconciliation_is_attempted`). **What does not exist:** no real broker export has ever been parsed (the CSV layout is an assumption; see LIMITATIONS.md); the 5 s tolerance is a documented default, not calibrated on data; nothing proves the broker file is complete or that the log's newest lines are still there (tail truncation is undetectable, so a MISSING_IN_LOG can be a deleted log tail); fees and partial fills are not reconciled; the class names are `AMBIGUOUS`/`MISSING_*` (the brief's word `UNKNOWN` is not used). | `.venv/bin/python -m pytest tests/test_recon.py tests/test_fills_csv.py -q` |
| 7 | **Durability before reply:** with `per_order` and `batched`, a reply is sent only after the fsync that covers its event, and a failed fsync yields no acknowledgement. | `tests/test_durability.py::test_no_reply_before_its_fsync[per_order]` and `[batched]` (a deliberately slow fsync is injected under a real TCP server with 4 pipelining clients; every reply is checked against the fsyncs that had completed when it arrived; `per_order` does one fsync per event, `batched` fewer); `::test_failed_fsync_means_no_acknowledgement`; `::test_full_fsync_uses_f_fullfsync_not_os_fsync` | `.venv/bin/python -m pytest tests/test_durability.py -q` |
| 7a | **Negative control** for 7: the durability check itself can fail. | `tests/test_durability.py::test_the_check_catches_a_reply_sent_before_fsync` runs a gate that answers *before* writing and fsyncing and asserts the checker flags it. | `.venv/bin/python -m pytest tests/test_durability.py -q -k catches` |
| 8 | **Process-crash recovery:** after `kill -9` of the gate at a random point under `per_order` and `batched`, the restarted gate's log verifies, contains every event whose reply the client received, has no duplicated `client_order_id`, returns the original decision for resent orders, and replays to the same state hash. **This is a process crash, not power loss** — a killed process leaves its `write()`s in the kernel's page cache, so fsync is not what these tests exercise. | `tests/test_crash_recovery.py::test_sigkill_loses_no_acknowledged_order` (2 policies x 3 seeds, real subprocess, 4 pipelining connections) | `.venv/bin/python -m pytest tests/test_crash_recovery.py -q -k sigkill` |
| 8a | **Torn tail:** a partial last line (no trailing newline) is truncated at startup with the bytes kept in `<log>.torn.<ns>` and a note in `<log>.recovery.jsonl`; the auditor reports it but never repairs; any other corruption (for example an edit in the middle) makes the gate refuse to start and leaves the file untouched. | `tests/test_crash_recovery.py::test_torn_tail_is_truncated_kept_and_noted`, `::test_garbage_after_the_last_newline_is_also_a_torn_tail`, `::test_only_a_missing_newline_is_repaired_other_corruption_refuses_to_start`, `::test_log_that_is_only_a_torn_line_becomes_empty` | `.venv/bin/python -m pytest tests/test_crash_recovery.py -q -k "torn or missing_newline"` |
| 9 | Every benchmark run is verified: chain intact, event count and accept/reject totals equal the reference model's, no auditor findings. A run that fails is marked invalid and not reported. | Enforced in `bench/run.py::run_once` after every run; failures are listed under "Failures" in `docs/PERFORMANCE.md`. | `make bench BENCH_N=20000 BENCH_REPS=1` |
| 10 | **Counterfactual parity:** replaying past trades through `auditor.counterfactual` gives the same ACCEPT/REJECT and reason code for every order as the real gate gives when the same orders are sent in the same order with the same timestamps (including after earlier blocks change later state), and the P&L impact equals the hand-computed value. | `tests/test_counterfactual.py::test_fixture_orders_get_the_same_decisions_from_the_real_gate` (17 orders through the real `Gate`); `::test_property_random_streams_decide_like_the_gate` (Hypothesis, random streams under tight rules so all rules fire; a mutation that applies only accepted trades to the Book was checked to fail it); `::test_matches_the_hand_computed_answers` (9 accepted / 8 blocked, evidence per block, original net -101,990 vs -96,590 with the rules, impact +5,400); `::test_a_blocked_trade_changes_later_decisions_so_it_is_not_a_subtraction`; `::test_replay_order_and_tie_break_are_by_ts_then_row_number`. **Not covered:** that the gate would have stamped the CSV's own timestamps (the replay assumes it); fills other than full fills at the order price. | `.venv/bin/python -m pytest tests/test_counterfactual.py -q` |

Power loss and OS crashes are **not** tested anywhere (see LIMITATIONS.md).

`policy none` (no fsync) is explicitly **not** covered by invariant 7: it replies after `os.write` only and is labelled
NON-DURABLE wherever it appears.
